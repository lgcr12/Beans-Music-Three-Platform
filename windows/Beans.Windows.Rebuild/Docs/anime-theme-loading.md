# 首页与详情页主题曲加载

2026-09-27

## 问题

- 首页在历史放送列表替换本地预览后，只调用已有曲目匹配，没有获取远程番剧缺失的主题曲关系。清空卡片后可能一直没有内容。
- 详情页先等待作品简介/海报请求和全部关联专辑返回，再启动平台核验。
- 同一歌曲使用 Task.WhenAll 等待 QQ 与网易云全部完成，快平台和已命中的缓存也被慢平台阻塞。

## 改动

- 将作品资料刷新与主题曲加载拆为两个接口。详情页并行启动；已有资料立即显示。
- 主题曲优先使用已知资料、独立主题曲磁盘缓存或旧版 subject 缓存。远程关系确认后，专辑并发上限仍为 4；每完成一首就发布曲名和歌手。
- 独立主题曲缓存使用 themes-v1-{BangumiId}，有效期 7 天，重启可复用。空响应和失败不会覆盖已有曲目缓存。
- 首页每部作品拥有稳定展示位置，读取资料时显示状态；发现首曲即启动平台匹配，不等待其余专辑。无资料时显示说明。
- 详情页歌曲核验并发上限仍为 3；每个平台完成时更新对应入口。曲目身份、同版本匹配规则及播放前权限验证保持原逻辑。
- 生命周期取消后不更新视图；在释放并发限制器前等待子任务结束。

## 提前预取与完整结果缓存

- 新增应用级单例 AnimeThemePrefetch。应用启动后即读取当天首页快照并获取历史放送名单，提前加载前三部作品的主题曲及平台匹配。
- 番剧索引、系列版本卡片显示时预取前三个候选。推测预取同时最多 3 个作品，每个作品最多并发匹配 2 首；直接打开的作品可立即开始，不排在其他预取任务后面。
- 同作品的预取、首页和详情页共享同一个进行中的任务。页面取消仅移除订阅，应用级任务继续执行；每项任务有 60 秒时间上限。
- 页面构造时先显示内存快照，再订阅增量结果。完整结果另存 ready-themes-v1-*，正常结果有效期 6 小时；部分未匹配结果保存快照但仅短暂复用 2 分钟。过期快照先展示，再后台刷新。
- 缓存只保存曲目身份，主动剔除播放 URL、PayloadReference 与已授权播放标记。真正播放时继续验证平台权限。
- 新增 4 项测试：启动时页面未打开也会预取；页面复用同一请求；取消一个页面不影响另一个页面或预取；重启直接复用安全缓存；过期缓存先显示后更新（部分场景合并在同一测试）。完整测试 452 项通过。
- 首次使用且没有缓存时仍受外部接口速度影响；不承诺任意番剧首次打开零等待。未添加系统自启动或常驻外部进程。
- 启动验证：2026-09-27 19:49:11 启动额外验证实例，未打开二次元页面，当秒生成当天首页快照，19:49:12 更新作品 513345 的 ready 缓存。现场缓存共 3 部作品、12 个曲目版本，10 个已有平台匹配。另两部复用之前生成的缓存；此结果不是首次无缓存耗时基准。确认后关闭自己额外启动的进程 31768，保留用户已运行的新版本进程 27688。
