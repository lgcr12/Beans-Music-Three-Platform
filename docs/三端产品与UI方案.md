# Beans Music 三端产品与 UI 方案

## 1. 产品目标与端侧选择

| 平台 | 客户端形态 | 目标 |
|---|---|---|
| iPhone / iPad | 现有 SwiftUI `Beans` | 完整移动体验、扫码、后台音频、下载与本地音乐 |
| macOS | 现有 `BeansCatalyst` 作为正式版 | 直接获得 iOS 全部平台、账号、歌单和播放器能力；针对宽屏使用三栏布局 |
| Windows 10/11 | Tauri 2 + React/TypeScript | 安装包小、系统媒体键/托盘支持好，通过统一 API 获取账号、授权和歌单 |

原生 `BeansMac` 继续作为纯本地音乐实验版，不作为“三端功能一致”的正式 Mac 客户端。

## 2. 三套可切换视觉风格

三套风格共享同一信息架构、组件尺寸和无障碍规则，只切换设计 token。入口为“我的 → 设置 → 外观 → 参考图风格”。

### 青碧玻璃（参考图一）

- 深青背景、薄玻璃面板、青绿主按钮、暖金环境光。
- 首页使用大幅推荐横幅；歌单和专辑使用大圆角卡片。
- 播放页以封面、歌词和柔和粒子背景为中心。
- 适合默认主题，深浅模式跟随系统。

### 清透纸感（参考图二）

- 大面积浅灰白、低阴影、绿色点缀、紧凑表格。
- 桌面端左侧导航 + 中央内容 + 右侧下载/本地音乐状态。
- 移动端使用四标签底栏；列表优先，降低装饰密度。
- 适合办公和日间使用，默认浅色。

### 午夜霓虹（参考图三）

- OLED 黑和午夜蓝底色，青/蓝/紫频谱高亮。
- 桌面播放页采用“导航—舞台—队列”三栏。
- 歌词当前行高亮，封面旁展示真实音频频谱；关闭粒子时保留静态渐变。
- 适合夜间、耳机和大屏，默认深色。

### 通用设计 token

- 字体：Apple 端使用系统字体；Windows 使用 Segoe UI Variable。正文最小 13pt/14px。
- 圆角：小控件 10，卡片 16，主面板 22，弹层 28。
- 间距：4/8/12/16/24/32；触控热区不小于 44×44。
- 动效：点击 150ms，页面 220ms，弹层 320ms；遵循系统“减少动态效果”。
- 对比度：正文至少 4.5:1；焦点、键盘导航和错误状态不能只靠颜色表达。
- 图标：统一使用 SF Symbols / Fluent Icons 的语义映射，不混用表情符号。

## 3. 统一信息架构

### 移动端

底栏固定为“主页、搜索、音乐库、我的”。迷你播放器悬浮在底栏上方。播放详情包含封面/频谱、歌词、队列、设备切换和音质。

### 桌面端

左栏为主页、搜索、音乐库、下载、本地音乐和歌单；中栏为当前业务；右栏按场景展示播放队列、歌词或设备。底部为全局播放器，点击进入全屏播放舞台。

窗口小于 900px 时自动收起右栏，小于 680px 时左栏折叠为图标栏。

## 4. Beans 本体账号注册链路

### 邮箱注册

1. 输入昵称、邮箱和密码，同意隐私政策与用户协议。
2. 客户端调用 `POST /v1/auth/register`，服务端发送 6 位邮箱验证码。
3. 调用 `POST /v1/auth/verify-email` 完成验证并签发 15 分钟 access token 与 30 天 refresh token。
4. 创建端到端加密保险库：密码经 Argon2id 派生本地密钥，服务端仅保存密文。
5. 引导授权 QQ 音乐和网易云音乐，最后选择首次同步的歌单范围。

密码不得保存在 UserDefaults。Apple 端 token 放 Keychain，Windows 放 Credential Locker；服务端密码使用 Argon2id 哈希。

### 普通登录

邮箱 + 密码 → 可选二次验证 → 下载加密保险库和歌单增量 → 恢复平台授权状态。连续失败 5 次触发短时限制，并提供设备/会话管理。

### 扫码登录本体账号

1. 待登录设备调用 `POST /v1/qr-sessions`，显示只含 `session_id + nonce` 的二维码，有效期 120 秒。
2. 已登录设备扫描后展示设备名、系统、城市和授权范围。
3. 用户点击“确认登录”，签名调用 `POST /v1/qr-sessions/{id}/approve`。
4. 待登录端通过 WebSocket 或 2 秒退避轮询取得一次性 exchange code。
5. exchange code 只能使用一次，换取该设备自己的 token；二维码中禁止携带 access token、密码或平台 Cookie。

## 5. QQ 音乐与网易云授权

- QQ 音乐和网易云可在未登录 Beans 本体账号时独立授权；登录 Beans 后才启用授权保险库与跨端同步。
- 授权在官方网页/二维码环境完成，客户端捕获登录结果后立即验证账号资料。
- 平台凭证写入本地安全存储；需要跨端共享时先在客户端端到端加密，再上传密文保险库。
- 服务端数据库不保存明文 Cookie，也不代替用户执行购买、续费或绕过会员权限。
- 授权状态包括：正常、即将过期、已过期、需要重新确认；播放失败不能直接等同于授权失效。
- 用户可以单独撤销某个平台、删除云端密文、踢出设备或一键注销 Beans 账号。

## 6. 数据同步模型

同步对象：自建歌单、收藏映射、播放历史、主题、播放器设置、设备列表，以及 QQ/网易云歌单的只读镜像。下载文件和用户导入的本地音频默认不同步。

- 每条记录包含 `id / revision / updated_at / deleted_at / device_id`。
- 客户端使用增量游标 `GET /v1/sync?cursor=...`，修改通过批量 `POST /v1/sync`。
- 自建歌单使用字段级最后写入优先；同一歌单并发排序使用 position key，避免整表覆盖。
- 平台歌单保存平台 ID 和歌曲统一标识，不复制受版权保护的音频文件。
- 离线修改进入本地 outbox；联网后自动重放，失败显示可恢复状态。

## 7. 后端 API 最小集合

`/v1/auth/register`、`/verify-email`、`/login`、`/refresh`、`/logout`

`/v1/qr-sessions`、`/{id}/approve`、`/{id}/exchange`

`/v1/me`、`/devices`、`/devices/{id}`、`/vault`、`/sync`

`/v1/platforms/qq/status`、`/platforms/netease/status`、`/platforms/{name}/revoke`

生产环境必须具备 TLS、审计日志、速率限制、密钥轮换、数据库备份和账号删除任务。日志不得记录 Cookie、密码、验证码、完整 token 或保险库明文。

## 8. 功能优化优先级

### P0：可用与安全

- Beans 真账号服务、邮箱验证、扫码登录、Keychain/Credential Locker。
- 歌单增量同步、冲突处理、设备管理、授权过期恢复。
- QQ 会员歌曲 vkey/media_mid/CDN 回退和播放器失败重试。
- 崩溃恢复、断网 outbox、无障碍与减少动态效果。

### P1：三端体验一致

- Windows 播放内核、系统媒体键、托盘、任务栏进度。
- Mac/Windows 三栏布局，移动端单栏导航。
- 三套主题 token、主题跨端同步、统一空状态和骨架屏。
- 播放队列、历史、收藏、自建歌单和播放进度同步。

### P2：体验增强

- 设备接力播放、局域网投送、跨端续播。
- 智能合并重复歌曲、失效歌曲替换建议。
- 动态频谱、歌词翻译、桌面迷你模式和快捷键中心。

## 9. 交付与验收

- iOS：真机后台播放、扫码、平台授权、断网恢复、IPA 签名验证。
- macOS：以 Catalyst 正式版验证全部 iPhone 功能，再验证键盘、窗口缩放和菜单栏。
- Windows：Windows 10 22H2 与 Windows 11 验证安装、卸载、自动更新、媒体键和休眠恢复。
- 同一测试账号在三端登录后，歌单/收藏/主题在 5 秒内增量同步；撤销设备后旧 token 立即失效。
- 账号与平台授权数据通过安全审计后才允许生产发布。
